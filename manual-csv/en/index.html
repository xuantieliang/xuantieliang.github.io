Bring your records with you

CSV Import Guide

Bring your existing transactions into Pennyworth using a CSV file exported from the app, or data from another service saved in the same format. Keep income and expenses in one file and transfers in a separate file, then import one file at a time.

The easiest way to get started is to export a file from Pennyworth and use its column headers as your template. CSV imports cover transactions, not a full book backup: they do not restore photos, budgets, or app settings.

Before you import

You cannot undo an entire import in one step. Back up your book first. If you are moving data from another app, try a few transactions in a separate test book and check the dates, amounts, and accounts before importing the rest.

Import your file

  1. Switch to the book you want to use, then open Settings and choose Import CSV.
  2. Check the book shown next to “Import into”.
  3. Tap Choose CSV File and select a file. The filename can be anything; Pennyworth uses the column headers to tell whether it contains income and expenses or transfers.
  4. Once the file has been checked, review its name, type, and number of records. Nothing has been added to your book yet.
  5. Tap the import button showing your book’s name. The completion message shows the number of records processed and a tag summary. Totals for the accounts involved are also updated.

A file can pass the initial check but still run into an account issue during import, such as a currency mismatch or more than one matching account. If the import fails, none of that file’s changes are saved. Fix the problem and select the file again.

Prepare your CSV

  • Put the column headers in the first row and your transactions in the rows below.
  • Save the file with UTF-8 encoding for best results.
  • Use either the standard format, with commas between columns and a period for decimals, or the European format, with semicolons between columns and a comma for decimals. Use one format throughout the file.
  • Unrecognized extra columns are ignored. However, mixing columns specific to income and expenses with columns specific to transfers can prevent the app from identifying the file type.

Sample CSV files

Income and expenses: standard format

Date,Category,Category Group,Amount,Currency,Account,Member,Tags,Memo,Income/Expenses,Post Date
20261123,Dining out,Everyday spending,18.50,USD,Cash,Me,Everyday|Food,Lunch,Out,
2026-11-23,Salary,,3200,USD,Bank account,Me,,November salary,In,
2026-11-24,Dining out,Everyday spending,-5,USD,Cash,Me,,Refund,Out,
2026-11-24,Household,Everyday spending,42.90,USD,Credit card,Me,Home,"Detergent,paper towels",Out,2026-11-26

Transfers: standard format

CSV
Date,From Account,Amount (From),Currency (From),To Account,Amount (To),Currency (To),Tags,Memo
20261123,Bank account,100,USD,Cash,,USD,Everyday,Cash withdrawal
20261124,Euro account,100,EUR,Bank account,108,USD,Travel,Currency exchange

The first transfer uses the same currency on both sides, so 100 USD leaves the bank account and enters the cash account. The second uses different currencies: the amounts entered in the file move 100 EUR out and 108 USD in.

Income and expenses: European format

CSV
Date;Category;Category Group;Amount;Currency;Account;Member;Tags;Memo;Income/Expenses
2026-11-23;Food;;12,50;EUR;Cash;Me;Travel;Lunch;Out

Semicolons separate the columns in this example. The amount 12,50 means 12.50 euros. With this format, do not change it to 12.50 or use periods to group thousands.

Common errors and fixes

ProblemWhat to check
File type not recognizedMake sure the first row contains column headers. Do not mix columns specific to income and expenses with columns specific to transfers.
Required column missingKeep required columns such as Category Group and Memo even if every cell below them is blank. Check that the headers match the names listed above.
Member is blankEnter a member’s name for every income or expense record, including updates. An empty cell or spaces alone will not work.
Duplicate or ambiguous columnsCheck that you have not included the same field twice under different names. For transfers, use Currency (From) and Currency (To) for the two currencies.
Row has the wrong number of columnsLook for a missing separator. If a memo contains commas, semicolons, or line breaks, enclose the whole cell in double quotes.
Invalid dateUse a complete date with a four-digit year. Check the month, day, and any time you include. Excel date serial numbers and incomplete times are not supported.
Invalid amountCheck whether the file uses standard or European formatting. Remove currency symbols, spaces used to group digits, and formulas. For transfers between different currencies, the amount received cannot be zero.
Invalid income/expense valueUse In or Income for income, or Out, Expense, or Expenses for expenses.
Currency does not match an existing accountCheck the account name and currency in the CSV, or create an account with the correct currency in the app first.
Multiple accounts have the same name and currencyGive the accounts distinct names in the app, then update the names in your CSV to match.
Sending and receiving accounts are the sameChoose two different accounts. Changing capitalization or adding spaces around a name does not make it a different account.
Post Date is earlier than the transaction dateSet Post Date to the transaction date or a later date.
Tags do not meet the requirementsCheck for more than 10 tags on a record, names that are too long, or unsupported or hidden characters.
File is empty or cannot be readMake sure it is saved as a CSV with valid text encoding and at least one transaction below the headers. If it is stored in the cloud, check that the entire file can be downloaded.
Importing again creates duplicate recordsCheck that each UUID matches an existing record in the destination book. Matching dates and amounts alone do not merge records or prevent duplicates.
